# M2C Comparison Features and Deterministic-Anchor Evidence

**Status:** Implemented development increment  
**Package version:** `0.1.0.dev4`  
**Authority:** Pair evidence only

## Purpose

M2C converts bounded M2A candidate pairs and M2B canonical tables into model-ready comparison features. It also evaluates configured deterministic anchors as a separate evidence stream. These components do not calculate match probabilities, solve assignment, classify relationships, or merge records.

## Comparison-feature contract

`DuckDBComparisonFeatureBuilder` consumes:

- one bounded candidate `TableRef`;
- one prepared left dataset;
- one prepared right dataset;
- validated `ComparisonConfig` objects.

It returns one row per candidate pair. Pair-key and retrieval-rule provenance are retained, while source field values are not copied to the output feature table.

For each comparison, the output contains stable internal columns for:

```text
numeric comparison value
configured comparison-level index
exact-agreement indicator
left-missing indicator
right-missing indicator
both-missing indicator
any-missing indicator
```

The integer level is the zero-based position of the first applicable level in the validated configuration. When a comparison omits a missing level, missing pairs receive `NULL` rather than being silently classified into the fallback level.

## Implemented comparison semantics

| Configured function | M2C value |
|---|---|
| `exact` | `1.0` for equality and `0.0` otherwise |
| `categorical` | `1.0` for equality and `0.0` otherwise |
| `jaro_winkler` | DuckDB Jaro–Winkler similarity in `[0, 1]` |
| `levenshtein` | length-normalised similarity in `[0, 1]`; optional maximum distance maps larger distances to `0.0` |
| `damerau_levenshtein` | length-normalised similarity in `[0, 1]`; optional maximum distance maps larger distances to `0.0` |
| `qgram` | Dice similarity over distinct configured q-gram sets in `[0, 1]` |
| `date_difference` | absolute configured day, month, or year difference |
| `numeric_difference` | absolute numeric difference divided by the configured positive scale |

All SQL is generated by package code from validated, allow-listed configuration objects. No raw SQL or callable is accepted from project configuration.

## Deterministic-anchor evidence

`DuckDBAnchorEvidenceEvaluator` compiles the existing safe anchor predicate tree:

- exact equality;
- prefix equality;
- date window;
- conjunction;
- disjunction.

The evaluator operates over prepared canonical datasets and produces one evidence row per matching pair and anchor rule. Each row includes:

```text
left and right surrogate record keys
anchor rule ID
left-side match count
right-side match count
left uniqueness flag
right uniqueness flag
combined uniqueness-pass flag
evidence_action = evidence_only
eligible_as_training_truth = false
```

Uniqueness is evaluated per anchor rule. A configured requirement passes only when the applicable side has exactly one matching record. The current configuration schema fixes anchor action to `evidence_only` and training eligibility to false.

## Budget and privacy controls

- Anchor pair count is checked before materialisation.
- Candidate-to-prepared-table key coverage is checked before feature materialisation.
- Public results expose structural counts, schema digests, and internal column names only.
- Backend failures are translated to stable `ML-COMP-*` or `ML-ANCHOR-*` errors.
- Errors and object representations do not expose row values, original identifiers, local paths, or candidate-pair values.
- Tests and CI use generated synthetic rows only.

## Verification scope

The M2C test suite covers:

- exact, categorical, Jaro–Winkler, normalised edit, q-gram, date, and numeric metrics;
- configured level ordering;
- explicit and ignored missingness;
- deterministic internal feature-column names;
- anchor exact, prefix, date-window, conjunction, and uniqueness behaviour;
- empty anchor configurations;
- pair-budget enforcement before materialisation;
- value-safe unavailable-variable failures;
- absence of record values and candidate pairs from public representations.

Remote CI additionally verifies Python 3.12, the actual DuckDB runtime, Ruff, strict mypy, pre-commit, the complete synthetic-only test suite, wheel/source-distribution builds, and restricted distribution contents.

## Explicit limitations

M2C does not yet provide:

- Fellegi–Sunter parameter estimation or scoring;
- term-frequency adjustments;
- supervised pair classification;
- learned candidate ranking;
- probability calibration;
- assignment;
- relationship status;
- adjudication processing;
- automated merging or master-record creation.

## Next increment

M2D will add the Fellegi–Sunter baseline over M2C comparison levels, initially through a package-owned adapter and synthetic parity tests. Statistical scores remain evidence, not calibrated final decisions.

> Synthetic testing establishes software behaviour only. It does not validate linkage accuracy, calibration, fairness, sensitivity, positive predictive value, false-link rates, missed-link rates, or operational fitness on real populations or systems.
